Trace model

The trace model names every need type, every link type and every shared field. One shared file, xdmod/needs/needs_config.toml, defines them for every document of every repo (One shared needs configuration (XD-RULE-0007)). The tables on this page are generated from that file. The reasons behind the model are in The V-model and trace links.

Need types

Each need type has a directive name equal to its ID kind in lower case (.. sys-req:: for SYS-REQ-0012). A link type is declared only on the need type that holds it (Link types are declared on ... (XD-RULE-0002)).

Levels of detail

Domain repos refine the system model in their own model/ folder by SysML specialization (Domain repos refine the sys... (XD-ADR-0130)). The system model holds what crosses a domain boundary: blocks down to the product level, their ports, and interface defs at signal level. A domain model holds how the domain realizes a block: board defs with connector ports and pin maps, cable defs, external parts and board variants for EE; assembly defs with mechanical ports and assembly variants for ME. KiCad, WireViz and FreeCAD files implement the domain model and name its elements by ID. curatrix checks that every inherited port is redefined with a conforming port def, and derives realizes and conforms from the specialization (curatrix checks conformance... (XD-ADR-0132)). Each board def has one KiCad project, each cable def one harness, each assembly def one FreeCAD document; external parts have none (External parts and prototyp... (XD-ADR-0135)).

Two exceptions to the peer rule (Peer interfaces live in sys... (XD-RULE-0003)): SW reads the board pin maps from the EE model (SW reads the board pin maps... (XD-ADR-0131)), and ME writes board geometry into the KiCad files inside a co-design change (ME writes board geometry in... (XD-ADR-0134), proposed).

Definitions and instances

  • The definition holds the ID (The definition holds the tr... (XD-ADR-0117)): a SysML part def, a KiCad sheet file, a FreeCAD part file. Its usages are listed in an instances field, not as separate needs.

  • A usage gets its own ID <ID>.<n> (for example SYS-EL-0012.1) only if it has its own requirement.

  • Only model elements with trace links become needs (Only linked model elements ... (XD-ADR-0118)): satisfy, allocate, or a link from another repo.

Link types

The owner is the need type that holds the link. “Min” is the number of targets the schema requires. Some minimums depend on a field and are schema rules instead:

  • A domain requirement without an upstream link must have derived: true and a rationale.

  • raised_by is required for stakeholder needs with category: need or objective.

  • Every domain design element needs at least one realizes or satisfies (No orphan design elements (XD-RULE-0010)).

  • Coverage minimums are graph rules (Every system requirement is... (XD-RULE-0008), Every requirement is verified (XD-RULE-0009)), not single-need rules.

Notes on the fields:

  • status: draft needs take part in all structure checks, but don’t count as coverage. Generated needs take their status from the source (Retiring generated needs (XD-ADR-0119)): SysML metadata, the KiCad field Status, the FreeCAD property Status, or a Doxygen tag.

  • configs, where, verification_scope, config: see Variants (Variant fields configs, whe... (XD-ADR-0093), Coverage per configuration (XD-ADR-0094)).

  • ears, quantity, unit, min, max, nominal: requirement values (Requirement values are need... (XD-ADR-0076)).
