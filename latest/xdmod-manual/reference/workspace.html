Workspace

Paths, roles, environment and limits of an XDMOD workspace. Background: Many repos, one workspace.

Layout

The workspace root is the west topdir (One west topdir at the work... (XD-ADR-0061)). Every command runs from here (All commands run from the w... (XD-ADR-0060)); paths in output and documents are relative to it.

<workspace>/
  .west/                west config, incl. manifest.group-filter and the role
  .venv/                workspace venv: west, curatrix, pinned packages, opt/ tools
  .xdmod/               workspace-local tool configs, caches, limit overrides (not a repo)
  .claude/              links to the shared and per-repo agent skills and commands
  .worktrees/<branch>/  worktree sets for parallel work
  build/<area>/         all build output
  CLAUDE.md             launch file, copied from xdmod by the bootstrap
  <manifest repo>/
  xdmod/
  <design repos>/       one per domain, plus integration, at the top level
  tools/                zdocs, affirmatrix
  libs/                 SYSMOD library, PLEML, KiCad and FreeCAD libraries
  zephyr/  modules/     Zephyr and its allowlisted modules, if the project uses Zephyr

Design repos sit at the top level, because people and agents work in them. Dependencies go under tools/ and libs/ (Workspace paths (XD-ADR-0083)).

+ee,+kicad-3d

+me,+freecad-parts,+ee

plus the ME repo, the FreeCAD parts library, and the EE repo with the KiCad libraries (Roles: EE gets FreeCAD, ME ... (XD-ADR-0141))

+sw,+ee

ci-full

same as integration

what the full-set CI job uses; CI builds without CAD content (CI runs without CAD content (XD-ADR-0049))

Set or change the role with curatrix bootstrap --role <role>. curatrix update applies the group filter of the current role again, so a role that gains groups (for example me and sw in Phase 5) gets them on the next update. Repos that become inactive are left on disk.

Bootstrap

From an empty folder (example: the robot arm’s manifest repo):

git clone https://github.com/tiacsys/robarm-manifest
robarm-manifest/scripts/bootstrap.sh --role ee

bootstrap.sh creates .venv with west, runs west init -l and west update, installs curatrix from xdmod (editable), and hands over to curatrix bootstrap --role <role>. That command:

  1. sets the role’s group filter and runs west update;

  2. installs the active repos’ requirements.txt into .venv and their tools.yaml tools into .venv/opt/, with sha256 checks (Tool versions of the refere... (XD-ADR-0014));

  3. copies xdmod/launch/CLAUDE.md to the root (Agent material in each repo... (XD-ADR-0062)) and links .claude/ (The bootstrap assembles .cl... (XD-ADR-0103));

  4. installs the pre-commit hooks and the FreeCAD diff driver in every active repo (Pre-commit hooks (XD-ADR-0091));

  5. creates .xdmod/;

  6. runs curatrix doctor.

On branches, use curatrix update (it runs west update -k). Plain west update moves every project back to its pin, as a detached HEAD.

Environment

eval "$(curatrix env)" sets PATH (with .venv/bin), ZEPHYR_BASE, JAVA_HOME, the XD_KICAD_* and XD_FREECAD_PARTS library variables, the env: entries of the tools.yaml tools, and PYTHONDONTWRITEBYTECODE=1. curatrix run -- <cmd> runs any command with this environment and the default limits.

No user-global configuration is used. KiCad, FreeCAD and drawio get workspace-local config folders under .xdmod/ through curatrix launch (Pinned, isolated component ... (XD-ADR-0080)).

curatrix bootstrap and update also write shims into .venv/bin for every KiCad and FreeCAD program found on the machine (kicad-cli, kicad, eeschema, pcbnew, gerbview, pl_editor, … and every freecad* program; KiCad and FreeCAD never run... (XD-ADR-0145)). From a worktree set they write the main workspace’s shims. A shim sets the same variables as curatrix run (KICAD_* and KICAD10_* for KiCad, LC_ALL for kicad-cli only, XDG_* for FreeCAD) and runs the real binary by its absolute path. With eval "$(curatrix env)" the shims come first on PATH; curatrix doctor warns when they do not, or when a shim’s real binary is gone. Nothing outside the workspace changes. The shims set no limits: still run the tools through curatrix.

Limits

Every tool runs under a memory limit and a timeout (A memory limit and a timeou... (XD-ADR-0064), Every tool runs under limits (XD-RULE-0044)). curatrix applies them itself from xdmod/curatrix/limits.yaml, which <workspace>/.xdmod/limits.yaml can override per key. curatrix limits shows the resolved table.

  • Backend: a systemd user scope with MemoryMax and no swap, plus timeout. Without a systemd user session, curatrix falls back to timeout plus ulimit -v.

  • Exit code 124 means timeout, 137 means killed for memory.

  • GUI tools started with curatrix launch get a memory limit only, no timeout (GUI tools get a memory limi... (XD-ADR-0106)).

  • Never raise a limit to make a runaway tool pass; find out why it runs away.

Does
