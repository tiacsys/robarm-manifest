ID scheme

Every need has an ID. IDs are stable, never reused, readable, and unique across the whole workspace. They work in every tool: sphinx-needs, SysML short names, KiCad fields, FreeCAD properties, Doxygen tags and test reports. The scheme is new; it does not reuse older ID schemes (A new ID prefix scheme (XD-ADR-0013)).

Format

<DOMAIN>-<KIND>-<NNNN>   e.g.  SYS-REQ-0012, SW-TC-0103, EE-CMP-0007, INT-ITC-0003
TR-<TESTCASE-ID>-<RUN>   e.g.  TR-SW-TC-0103-3f9a1c2e   (test results only)

  • DOMAIN: SYS, SW, EE, ME, INT (integration and system verification), XD for the framework’s own items and PRJ for project-level items (ID format DOMAIN-KIND-NNNN (XD-ADR-0071), Decisions become sphinx-needs (XD-ADR-0109)).

  • KIND: 2 to 5 capital letters. Domain and kind together name the need type.

  • NNNN: a number with 4 digits, zero-padded, issued per kind. Above 9999 it simply grows.

  • RUN: the first 8 hex digits of the run record’s hash (HIL runs) or of the JUnit file. So a test result is unique per run.

  • A usage of a definition may get <ID>.<n> (The definition holds the tr... (XD-ADR-0117)).

  • Regex: ^((SYS|SW|EE|ME|INT|XD|PRJ)-[A-Z]{2,5}-[0-9]{4,}|TR-(SYS|SW|EE|ME|INT)-[A-Z]{2,5}-[0-9]{4,}-[0-9a-f]{8})$

No project code in the sources (No project code in the sources (XD-ADR-0072)). All repos of a project share one ID space. Where IDs leave the workspace (bundles, published needs.json, shared affirmatrix cases), the exporting tool puts a project code in front, with : as the separator. Example (robot arm): RA:SYS-REQ-0012.

The ledger

Each repo keeps one ledger file, ids.yaml. It lists every number ever issued per kind that the repo owns, one per line. It is append-only. Listing every number (not just the last) means that two PRs that issue the same number touch the same line, so git reports a conflict (ID collisions show up as gi... (XD-ADR-0122)).

# Every number issued per kind, one per line. Append-only.
SYS-REQ:
  - 41
  - 42
SYS-NEED:
  - 17
SYS-FEAT: []       # owned, nothing issued yet

A kind with nothing issued yet is written KIND: []. That line makes the repo the owner of the kind.

Issuing IDs

  • Placeholders. Write a need with a placeholder ID of the form <KIND>-NEW-<tag>, for example the kind SYS-REQ followed by -NEW-a. Then run curatrix ids fix <repo>. It replaces every placeholder with the next free number (max(ledger, IDs in the sources) + 1) and adds it to the ledger. The same placeholder gets the same ID in every file.

  • curatrix ids new <KIND> [FILE] issues one ID, and with FILE replaces that file’s first placeholder of the kind.

  • Never invent a number. Never reuse one.

  • Parallel PRs. Two PRs may issue the same number. The second to rebase gets a ledger conflict. Rerun curatrix ids fix, which renumbers that PR’s new IDs. Rulesets require PRs to be up to date with main before merge, so the duplicate check runs on the combined state.

  • Retiring. A retired need keeps its ID with status: retired (Small corrections from rese... (XD-ADR-0057) (e), Retiring generated needs (XD-ADR-0119)). When it is finally deleted, the ledger still holds its number.
