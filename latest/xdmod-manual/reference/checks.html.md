# Checks

curatrix runs every check with one command per repo, from the workspace root ([*Every check runs locally (XD-RULE-0032)*](../explanation/rules/checks.html.md#XD-RULE-0032)):

```sh
curatrix check <repo> [--stage local|pr|full|baseline] [--no-cad] [--only IDs] [--json]
```

The check catalogue on this page is generated from curatrix. Each check is also a need
(`XD-CHECK`) that enforces one or more method rules; see [Check needs]() at the end.

| `pr`       | GitHub Actions per repo ([*GitHub CI builds docs and r... (XD-ADR-0041)*](../explanation/decisions/checks.html.md#XD-ADR-0041), [*CI runs without CAD content (XD-ADR-0049)*](../explanation/decisions/checks.html.md#XD-ADR-0049))                                  | the repo and its siblings on the same branch name ([*One branch name across repos (XD-ADR-0045)*](../explanation/decisions/workflow.html.md#XD-ADR-0045)) | no            | gate for merging                          |
| `full`     | the bump-bot job in the manifest repo ([*The bump bot is a scheduled... (XD-ADR-0081)*](../explanation/decisions/checks.html.md#XD-ADR-0081))                                                                                                                            | all repos at the new pins                                                                                                                                   | no            | cross-repo rules                          |

GitHub CI runs `--stage pr --no-cad`. Checks that need KiCad, FreeCAD or the SysML Pilot run
locally ([*CI runs without CAD content (XD-ADR-0049)*](../explanation/decisions/checks.html.md#XD-ADR-0049)). The committed CAD-derived needs let CI still see the full trace graph
([*CAD-derived needs are commi... (XD-ADR-0100)*](../explanation/decisions/checks.html.md#XD-ADR-0100)).

## Levels

- **error**: the finding fails the stage.
- **warning**: the finding is reported but does not fail.
- **report**: the finding adds a summary, for example to a PR.

## Domain checks

Repos add their own checks as `commands` in their `checks.yaml`. They are not curatrix
checks and have no `XD-CHECK` need. Typical domain checks compare domain content with the
interfaces in the systems engineering repo: a KiCad netlist against the pin maps, the Zephyr
devicetree against the model, FreeCAD parameters against model attributes, KiCad ERC and FreeCAD
recompute, the firmware build and unit tests.

Phase 5 plans more checks for the EE and ME domains (projects, 1:1 with the domain model,
connectors, ERC and DRC, accepted findings, jobsets, BOM fields, variants, assemblies, collisions)
and the domain-model conformance check ([*curatrix checks conformance... (XD-ADR-0132)*](../explanation/decisions/domains.html.md#XD-ADR-0132)). Their IDs, stages and levels are
fixed in `xdmod/claude/framework/checks.md` before their code; each starts as a warning and
appears in the catalogue above once it is built.

## Output

- Logs and a summary go to `build/<area>/checks/`. The summary JSON
  (`build/<area>/checks/summary.json`, also printed with `--json`) lists every check with its
  status (`pass`, `fail`, `warn`, `report`, `skip`), findings, log and reproduce command.
- For every failure, curatrix prints the command that reproduces it.
- A stage fails when any check has the status `fail`.

The format of `checks.yaml` is in the curatrix reference.
