Checks

curatrix runs every check with one command per repo, from the workspace root (Every check runs locally (XD-RULE-0032)):

curatrix check <repo> [--stage local|pr|full|baseline] [--no-cad] [--only IDs] [--json]

The check catalogue on this page is generated from curatrix. Each check is also a need (XD-CHECK) that enforces one or more method rules; see Check needs at the end.

Levels

  • error: the finding fails the stage.

  • warning: the finding is reported but does not fail.

  • report: the finding adds a summary, for example to a PR.

Domain checks

Repos add their own checks as commands in their checks.yaml. They are not curatrix checks and have no XD-CHECK need. Typical domain checks compare domain content with the interfaces in the systems engineering repo: a KiCad netlist against the pin maps, the Zephyr devicetree against the model, FreeCAD parameters against model attributes, KiCad ERC and FreeCAD recompute, the firmware build and unit tests.

Output

  • Logs and a summary go to build/<area>/checks/. The summary JSON (build/<area>/checks/summary.json, also printed with --json) lists every check with its status (pass, fail, warn, report, skip), findings, log and reproduce command.

  • For every failure, curatrix prints the command that reproduces it.

  • A stage fails when any check has the status fail.

The format of checks.yaml is in the curatrix reference.
