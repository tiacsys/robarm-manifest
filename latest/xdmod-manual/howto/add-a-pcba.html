Add a PCBA or circuit block

Use this guide when you add a KiCad project (a PCBA), a circuit block or a component that takes part in trace links. Prototype wiring is EE content too: a KiCad schematic of the prototype setup whose elements carry configs (Prototype wiring is EE content (XD-ADR-0067)).

The board itself is a def in the EE model; the KiCad project only names it (The domain model owns the I... (XD-ADR-0128)). Circuit blocks and components keep their trace IDs inside the KiCad files (Trace IDs live inside the C... (XD-ADR-0023)).

Steps

  1. Add the board def to model/ in the EE repo: part def <'EE-PCBA-NEW-a'> MyBoard :> <the SYS-EL def>, XdDomain::Pcba, with a connector port def (EE-PORT) for every port it inherits (Domain repos refine the sys... (XD-ADR-0130)). Run curatrix ids fix robarm-ee and curatrix gen model robarm-ee; realizes and conforms come from :>.

  2. Make the KiCad project in the EE repo (e.g. pcba/<name>/). Use only the workspace libraries: start KiCad with the launcher, which sets the library paths and keeps your user-global setup out (Pinned, isolated component ... (XD-ADR-0080)):

    curatrix launch kicad robarm-ee/pcba/<name>/<name>.kicad_sch

  3. For the PCBA itself, set the text variable TraceID in <name>.kicad_pro to the board def’s EE-PCBA ID: a reference, the need comes from the model. Nothing else goes there: Realizes, Configs or other link fields next to it are reported, because links and configs come from the model (configs from the SYS-CFG that configures the realized SYS-EL). A TraceID that is not a need of the model is reported too. For circuit blocks and components, add hidden symbol or sheet fields:

    Field

    Value

    TraceID

    the need ID (kind EE-CMP); write a placeholder ID, then issue it

    Realizes

    the product-layer SYS-EL IDs (comma list)

    Satisfies

    EE-REQ IDs

    Conforms

    SYS-IF IDs of the interfaces it meets

    PartOf

    the EE-PCBA ID

    Status

    draft, valid or retired

    Configs

    SYS-CFG IDs, if it belongs only to some configurations

    A sheet used several times carries one ID; its usages become instances (The definition holds the tr... (XD-ADR-0117)).

  4. List the root schematic in the repo’s checks.yaml under cad.kicad, then issue the IDs and regenerate the CAD needs:

    curatrix ids fix robarm-ee
curatrix gen cad-needs robarm-ee

    Commit generated/cad-needs.json (CAD-derived needs are commi... (XD-ADR-0100)).

  5. Show the schematic in the PCBA document with kicad-sheet, kicad-bom and kicad-nets. Make the exports locally with curatrix gen cad-exports robarm-ee. In CI the directives show a “built locally” notice (CI runs without CAD content (XD-ADR-0049)).

  6. If the board has variants (at most two, Variants: the domain varian... (XD-ADR-0136)): add them in KiCad as assembly variants (Board Setup or the schematic’s variant list; DNP and fields per variant), write one def per variant in the EE model (part def MyBoardAlt :> MyBoard, XdDomain::DomainVariant { :>> variantName = "alt"; }) with a dependency to the configurations and usages it serves, and add variants: true to checks.yaml (the check also needs model.upstream, the system repo’s committed generated/model.json).

Checks

  • cad-needs.json matches the ... (XD-CHECK-0019): cad-needs.json matches the KiCad files (plain Python, no KiCad needed).

  • the Pilot parses the model ... (XD-CHECK-0016), model.json and model-needs.... (XD-CHECK-0017): the EE model parses and its generated files are fresh.

  • domain model conforms to it... (XD-CHECK-0033): the board def redefines every inherited port with a fitting port def.

  • variants across levels: one... (XD-CHECK-0034): exactly one variant per configuration and usage, and each variant is in the .kicad_pro.

  • docs build strict (zdocs, s... (XD-CHECK-0001): the strict docs build; its needs schema fails an element that realizes or satisfies nothing (No orphan design elements (XD-RULE-0010)).

  • Domain checks such as the netlist against the interface pin maps, and ERC, are commands in the repo’s checks.yaml.

Pitfalls

  • Hidden fields are easy to lose when you replace a symbol. Check cad-needs.json in the diff.

  • There is one design document per PCBA and one per prototype configuration (One EE document per PCBA an... (XD-ADR-0102)).
