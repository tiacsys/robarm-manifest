Make a change across repos

Use this guide when one change touches more than one repo, for example a new system requirement plus the domain requirements and design that follow from it.

Steps

  1. One branch name for the change, in every repo it touches (One branch name across repos (XD-ADR-0045)), e.g. feat/latency. Work in a worktree set, so the main checkouts stay untouched (Parallel agents work in git... (XD-ADR-0114)):

    curatrix work start feat/latency robarm-syseng robarm-sw
cd .worktrees/feat/latency

    Builds of the set go to build/wt-feat-latency/.

    Note

    curatrix work is being added (task 4.4c). Until it is on main, make the worktrees by hand: git -C <repo> worktree add ../.worktrees/<branch>/<repo> -b <branch>.

  2. Author the change in each repo, run curatrix gen and curatrix ids fix where needed.

  3. Check every repo you touched, with CAD content where the repo has it (Every check also runs locally (XD-ADR-0040)):

    curatrix check robarm-syseng --stage local
curatrix check robarm-sw --stage local

  4. Open one PR per repo. Each PR lists its sibling PRs and the affected needs, and ends with the provenance trailer (Provenance trailer on GitHu... (XD-ADR-0065)).

  5. PR CI checks each repo without CAD content (CI runs without CAD content (XD-ADR-0049)). For sibling repos it uses, in this order: a branch with the same name; the repo’s main if the manifest pin is an ancestor of it; the manifest pin (PR CI sibling resolution (XD-ADR-0116)).

  6. Merge upstream first: syseng, then the domains, then integration. Framework changes merge before the repos that use them. Every PR is rebase-merged (Trunk-based merging with re... (XD-ADR-0043)).

  7. Bump. The bump bot in the manifest repo collects the new main SHAs into one bump PR and builds the full set (A bump bot for manifest pins (XD-ADR-0054), The bump bot is a scheduled... (XD-ADR-0081)). Merging it moves the pins (The manifest is the only pl... (XD-ADR-0033)).

  8. When everything is merged:

    curatrix work done feat/latency

Pitfalls

  • west update moves repos back to their pins (detached HEAD). On branches use curatrix update. Never run either inside a worktree set.

  • A ledger conflict after a rebase means two PRs issued the same ID. Rerun curatrix ids fix.
