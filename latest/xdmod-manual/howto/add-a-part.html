Add a FreeCAD part or assembly

Use this guide when you add a FreeCAD part (ME-PART) or assembly (ME-ASM) that takes part in trace links.

Steps

  1. Start FreeCAD with the launcher. It uses a workspace-local config that saves .FCStd files uncompressed and points at the pinned parts library (FreeCAD files uncompressed,... (XD-ADR-0056), Pinned, isolated component ... (XD-ADR-0080)):

    curatrix launch freecad robarm-me/parts/link.FCStd

  2. Add string properties in the group Trace to the part or assembly object: TraceID, Realizes, Satisfies, Conforms, PartOf, Status, Configs. They mean the same as the KiCad fields (Add a PCBA or circuit block).

  3. Set the TraceID to a real ID. Placeholders inside .FCStd files are refused, so issue the ID first:

    curatrix ids new ME-PART --repo robarm-me

  4. Keep parameters in a spreadsheet with aliases. The freecad-params directive shows them in the docs, also in CI.

  5. Regenerate the CAD needs and the semantic JSON, and commit both with the part:

    curatrix gen cad-needs robarm-me
curatrix gen freecad-json robarm-me

Checks

  • .FCStd uncompressed; drawio... (XD-CHECK-0025): the .FCStd is stored uncompressed (Design files are stored unc... (XD-RULE-0039)).

  • cad-needs.json matches the ... (XD-CHECK-0019): cad-needs.json matches the FreeCAD files.

  • generated files record the ... (XD-CHECK-0020): the generated files record the tool versions that made them.

For review, git diff shows .FCStd changes as semantic JSON through the textconv driver that the bootstrap installs. GitHub does not, so reviewers read the committed JSON.

Note

The full review report (drawing SVGs, image diff, 3D views) stays local in iteration 1 (Scope cuts for iteration 1 (XD-ADR-0124)). Publishing it as a Pages preview (FreeCAD review report as a ... (XD-ADR-0098)) comes later. The drawings and the exploded view of an assembly come from curatrix cam (see below); GLB exports are not implemented yet.

The local sections show only the curatrix cam output of the commit the repo is at (A board or assembly documen... (XD-RULE-0060)); CK-D10 warns locally when it is missing. Make it before you build the document:

curatrix cam robarm-me <name>
curatrix docs robarm-me

The mass is the solid volume of each present part times the density of its Material, or the part’s own Mass (12 g) or Density (1.24 g/cm^3) property; both need a unit, and a density outside 0.01 to 25 g/cm³ is refused. Printed parts count as solid; the infill of the print profile is not applied, so their mass is an upper bound. The center of gravity is in the frame of the top-level assembly. A sub-assembly chapter shows the mass of its first use; drawings, exploded view, renderings and parameters exist only for the top-level assembly (iteration 1), so these sections of a sub-assembly chapter print a fixed sentence.

In the BOM, a standard fastener (any object with a Standard property such as ISO 4762 M3x10, A2, usually in lib/) is named by its standard designation; another bought part (a lib/ object, or one with Manufacturer or MPN) names Manufacturer and MPN; a board model or harness is one line with its version and its pcba-<name> / harness-<name> document, its parts stay in the EE BOM. CK-F12 warns about a bought part without them and about an own part without Material (Every BOM part names its ma... (XD-RULE-0058)).

Pitfalls

  • .FCStd files can’t be merged. On a conflict, take one side and redo the other change.

  • An unchanged save still changes the file. The pre-commit hook warns when a .FCStd changed but its semantic JSON didn’t.
