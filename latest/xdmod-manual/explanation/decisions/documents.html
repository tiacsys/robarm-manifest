Framework Decision: WireViz for harnesses XD-ADR-0127
status: valid
date: 2026-11-17
decision_status: accepted
revises: XD-ADR-0102

WireViz is adopted for cables between boards and external parts. It is a pinned pip package (xdmod requirements.txt), plain Python with Graphviz, so CI and Pages can draw the diagrams too. Licence check (2026-11-17): WireViz is GPL-3.0, xdmod is Apache-2.0. curatrix runs the wireviz command as a separate process through curatrix run and never imports it, so it is used as a tool; its output (diagrams, BOMs) is not covered by the GPL. Each harness is one folder harness/<name>/ with one WireViz YAML <name>.yml as entry point, 1:1 with a cable def in the EE model (EE-HAR, The domain model owns the I... (XD-ADR-0128)). The connectors at both ends name the EE-PORT they mate with, also on external parts; CK-F1 checks pin to pin against both ends. curatrix cam makes the diagram, the harness BOM (with Manufacturer and MPN) and the version from tags <name>/vX.Y.Z. One harness in iteration 1. The harness length and route are a co-design value between EE and ME (task 5.28). Prototype jumper wiring stays a KiCad schematic per prototype setup (Prototype wiring is EE content (XD-ADR-0067)).
Framework Decision: One document per board, harness and assembly XD-ADR-0129
status: valid
date: 2026-11-17
decision_status: accepted
refines: XD-ADR-0102
revises: XD-ADR-0124
decides: XD-RULE-0050, XD-RULE-0058, XD-RULE-0059, XD-RULE-0060

Each board, harness and top-level assembly gets its own document from the start: pcba-<name> (and proto-<name> per prototype project), harness-<name> and asm-<name> (with one chapter per sub-assembly). ee-design and me-design keep the requirements and the overview. curatrix new pcba / new asm create the document and its registry entry. One directive set per document type, so all documents of one type look the same; a section without data prints one fixed sentence.

What CI can show: everything read in plain Python appears everywhere: stackup and design-rule tables, connector pin tables (from the committed generated/<project>.connectors.json), the BOM (in the appendix, one column per variant), the variants table, parameters, materials and interfaces of assemblies, the harness diagram and pin-to-pin table. What needs KiCad or FreeCAD (schematic, renderings, ERC/DRC findings, drawings, exploded view, mass and center of gravity) is included only in local builds, from build/<repo>/cam/, with the version it shows; CI and Pages show a placeholder. At the baseline stage, missing or stale local output is an error. A board or harness appears in the assembly BOM as one line with its version and a link to its document.
