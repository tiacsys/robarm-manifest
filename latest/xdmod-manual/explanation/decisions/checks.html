Framework Decision: A memory limit and a timeout for every tool XD-ADR-0064
status: valid
legacy_id: D71
date: 2026-11-14
decision_status: accepted
refined by: XD-ADR-0106
decides: XD-RULE-0044

Every tool runs with a memory limit and a timeout, for humans’ scripts and all agents alike. The limits are set per tool and use. Swap is off inside the limit, so a runaway tool is killed and can’t stall the machine or block agents. Interim wrapper: .venv/bin/xd-limit (systemd user scope + timeout); xdmod’s command layer takes this over (3.13).

Framework Decision: Checks that bite XD-ADR-0125
status: valid
date: 2026-11-17
decision_status: accepted
decides: XD-RULE-0045, XD-RULE-0046

A check run passes only if it checked something (Phase 4 review P4-4, P4-14; plan Phase 5, task 5.1). A missing checks.yaml and an empty plan fail. Each repo lists the checks it runs in expect:, so a lost section is an error (CK-H6); curatrix check prints the checks that are off and why. An error-level check that is skipped at the baseline stage fails. Failures of git and west are reported, never treated as “nothing found”. A pull request gets a warning when it changes more than 600 hand-written lines or 15 files against its base (CK-H7): one SYSMOD step or one tool feature per PR.
Framework Decision: One accepted.yaml format, with Accepted-by XD-ADR-0126
status: valid
date: 2026-11-17
decision_status: accepted
refines: XD-ADR-0051, XD-ADR-0123
decides: XD-RULE-0051, XD-RULE-0052

Accepted CAD findings live in one file format for EE and ME: pcba/<name>/accepted.yaml and assemblies/<name>/accepted.yaml, read by the same check code. An entry names the check, the rule, the items (designators or part names, never positions, so the entry survives a move; or all findings of one rule, as for unrouted nets) and the reason.

Only a human accepts. An entry counts as accepted only when the commit that added it carries an explicit Accepted-by: <name> trailer, has no agent trailer, and changes nothing but acceptance entries. Agents never write Accepted-by:; an entry from an agent commit, or not yet committed, is a proposal (Only a human's commit affirms (XD-ADR-0051)): a warning locally, an error at the baseline. Real enforcement (commits signed with a key only the owner holds) stays in iteration 2 (Agent limits are policy onl... (XD-ADR-0123)).

  • Only errors must be accepted; warnings are listed and never fail.

  • KiCad’s own exclusions stay for single, stable findings, under the same rule: an exclusion counts as accepted only when the commit that added it to the .kicad_pro carries Accepted-by:, has no agent trailer and changes nothing but exclusions or acceptance entries; otherwise it is a proposal. Stated rule: a KiCad exclusion is lost when its items move. An ERC exclusion counts only if no finding of the same type and items is reported as not excluded, because KiCad turns a stale ERC exclusion into an excluded phantom finding (KiCad spike §4.4).

  • A board’s ERC and DRC severities must equal those of the curatrix new pcba template (a missing erc section counts as KiCad’s defaults). A difference is a finding that needs acceptance, so a severity cannot silently switch a rule off.

  • The reports stay local; CI and Pages show a placeholder in the findings section.
