status: valid
legacy_id: D88
date: 2026-11-14

Component libraries are pinned west projects, isolated from user-global setups. EE uses the tiacsys KiCad libraries (kicad-symbols, kicad-footprints, kicad-packages3D, kicad-templates, kicad-library-utils). ME uses the FreeCAD parts library (FreeCAD/FreeCAD-library). KiCad projects use project-local library tables that point into the workspace through variables, and the GUI launchers (All commands run from the w... (XD-ADR-0060), 3.13) set those variables. FreeCAD gets its parts path from its launcher. User-global libraries are not used. The big libraries (kicad-packages3D about 1.8 GB, FreeCAD-library about 5.7 GB) get their own groups (West submanifests and proje... (XD-ADR-0079)) and shallow clones.

Framework Decision: Tags per board, assembly and harness, made by the owner XD-ADR-0140
status: valid
date: 2026-11-17
decision_status: accepted
refines: XD-ADR-0047
decides: XD-RULE-0054

Boards, assemblies and harnesses have their own tags <name>/vX.Y.Z (for example joint-controller/v1.2.0) in their domain repo, next to the repo tags (SemVer tags and baseline tags (XD-ADR-0047)). The design output takes its version from git describe --match '<name>/*'. ME tags only assemblies; an exported part carries the version of the assembly. Only the owner creates these tags, like baselines; an agent proposes a tag in its PR. Unfinished designs use v0.x tags, as the owner set for the canary (Phase 5 plan review, P5-12).
Framework Decision: Roles: EE gets FreeCAD, ME gets the KiCad files, SW gets the EE model XD-ADR-0141

  • me also needs the EE repo with the KiCad libraries (west group ee, without the 3D models) and kicad-cli: StepUp pushes into the .kicad_pcb, and the pushed file is re-saved by KiCad 10 (ME writes board geometry in... (XD-ADR-0134)).

  • sw also gets the EE repo (west group ee): SW reads the board pin maps from the EE model (SW reads the board pin maps... (XD-ADR-0131)).

  • Both ee and me get the board library repo once it exists (A board library repo for ME (XD-ADR-0139)).

tools.yaml and the roles of curatrix bootstrap follow; curatrix doctor warns when a role with kicad-cli has no KiCad 3D models (STEP and renderings then show bare boards).
Framework Decision: KiCad and FreeCAD never run outside curatrix; shims in .venv/bin XD-ADR-0145
status: valid
date: 2026-11-17
decision_status: accepted
refines: XD-ADR-0080

Never run KiCad or FreeCAD outside curatrix or its shims, not even --version. A bare kicad-cli --version rewrites ~/.config/kicad/10.0/kicad_common.json; agents did this twice. As a safety net, curatrix bootstrap and update write shims into the main workspace’s .venv/bin (also when run from a worktree set) for every KiCad and FreeCAD program on the machine: kicad-cli, kicad, eeschema, pcbnew, bitmap2component, each program with a KiCad .kiface (gerbview, pl_editor, pcb_calculator, …) and every freecad* program in any case (FreeCAD, FreeCADCmd, freecad, freecadcmd, …). A shim sets the workspace-local config that curatrix run sets (LC_ALL only for kicad-cli; the GUIs keep the user’s locale) and runs the real binary, found by absolute path when the shim is written (never .venv/bin itself or another shim). KiCad’s IDF converters (idfcyl, dxf2idf, …) write no config and get no shim. curatrix env puts .venv/bin first on PATH; curatrix doctor warns when a KiCad or FreeCAD name on PATH is not the shim, or a shim’s real binary is gone. Nothing outside the workspace changes: no user-global files, no PATH edits in shell profiles. The shims set no limits, so the tools still run through curatrix (A memory limit and a timeou... (XD-ADR-0064)).
