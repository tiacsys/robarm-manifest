Workflow and agents

Branches, merging, reviews, and what agents may do.

Framework Decision: Agents are first-class XD-ADR-0003
status: valid
legacy_id: D3
date: 2026-11-14
decision_status: accepted
refined by: XD-ADR-0051

Agents are first-class: they edit and review design content the same way human engineers do.
Framework Decision: Trunk-based merging with rebase XD-ADR-0043
status: valid
legacy_id: D50
date: 2026-11-14
decision_status: accepted
followed by: PRJ-DEC-0017

Merging: trunk-based on main. Every change goes through a PR, required checks must pass, and PRs are rebase-merged (linear history). Enforced with org rulesets.
Framework Decision: Agents work under the user's account XD-ADR-0044
status: valid
legacy_id: D51
date: 2026-11-14
decision_status: accepted
refined by: XD-ADR-0065, XD-ADR-0108, XD-ADR-0123
decides: XD-RULE-0042
followed by: PRJ-DEC-0016

Agent identity: agents work under the user’s account, and their commits carry a Co-Authored-By trailer. GitHub does not let you approve your own PR, so rulesets require passing checks but no approval count. The user’s review and merge is the approval.
Framework Decision: One branch name across repos XD-ADR-0045
status: valid
legacy_id: D52
date: 2026-11-14
decision_status: accepted
refined by: XD-ADR-0054, XD-ADR-0116

Changes across repos: the same branch name is used in every repo the change touches. CI checks out sibling repos at that branch if it exists, otherwise at the manifest pin. Upstream merges first, then one manifest PR bumps all pins.
Framework Decision: Planning with plan.md, issues and PRs XD-ADR-0046
status: valid
legacy_id: D53
date: 2026-11-14
decision_status: accepted

Planning: plan.md stays the master plan. Tasks become GitHub issues in the repo where the work happens, and PRs close them. An org Projects board is optional.
Framework Decision: Only a human's commit affirms XD-ADR-0051
status: valid
legacy_id: D58
date: 2026-11-14
decision_status: accepted
refines: XD-ADR-0003
refined by: XD-ADR-0126
followed by: PRJ-DEC-0016

X3 Agents and evidence: agents analyse suspect links and prepare affirmations and verdicts, but only a human’s commit counts as an affirmation or verdict. Refines Agents are first-class (XD-ADR-0003).
Framework Decision: Provenance trailer on GitHub posts XD-ADR-0065
status: valid
legacy_id: D72
date: 2026-11-14
decision_status: accepted
refines: XD-ADR-0044

Provenance on GitHub: everything an agent posts on the user’s behalf (issues, comments, PR descriptions, reviews, release notes) ends with the trailer 🤖 Generated with [Claude Code](https://claude.com/claude-code). Commits keep the Co-Authored-By trailer. Extends Agents work under the user'... (XD-ADR-0044).
Framework Decision: Sign-off by agents XD-ADR-0108
status: valid
legacy_id: D119
date: 2026-11-14
decision_status: accepted
refines: XD-ADR-0044

Sign-off: agents may add Signed-off-by in the user’s name where a repo’s convention requires it, always together with the Co-Authored-By trailer. The user certifies by reviewing and merging.
Framework Decision: GitHub admin by agents only after approval XD-ADR-0112
status: valid
legacy_id: D123
date: 2026-11-14
decision_status: accepted
followed by: PRJ-DEC-0012

GitHub admin by agents (repos, rulesets, labels, Pages settings) only after the owner approves each concrete action list.
Framework Decision: Posting approval outside our repos XD-ADR-0113
status: valid
legacy_id: D124
date: 2026-11-14
decision_status: accepted

Posting approval: agents post freely in robarm-* and xdmod (with the trailer). On other repos (zdocs, affirmatrix, upstream projects), they draft first and post after the owner’s approval.
Framework Decision: Parallel agents work in git worktrees XD-ADR-0114
status: valid
legacy_id: D125
date: 2026-11-14
decision_status: accepted

Parallel agents work in git worktrees under <ws>/.worktrees/<branch>/<repo> (curatrix work start/done). Shared parts aren’t duplicated, and builds go to build/<branch>/.
Framework Decision: Every PR gets an agent review XD-ADR-0115
status: valid
legacy_id: D126
date: 2026-11-14
decision_status: accepted

Every PR in robarm-* and xdmod gets an agent review (by an agent other than the author, /review-pr) before the owner’s review.
Framework Decision: Agent limits are policy only in iteration 1 XD-ADR-0123
status: valid
legacy_id: D134
date: 2026-11-14
decision_status: accepted
refines: XD-ADR-0044
refined by: XD-ADR-0126

Agent limits stay policy only in iteration 1 (agents use the owner’s login, Agents work under the user'... (XD-ADR-0044)). Technical enforcement (a GitHub App identity or signed commits) is in the iteration 2 backlog.
