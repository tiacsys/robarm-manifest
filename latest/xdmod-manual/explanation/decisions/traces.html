Framework Decision: ID format DOMAIN-KIND-NNNN XD-ADR-0071
status: valid
legacy_id: D78
date: 2026-11-14
decision_status: accepted
refined by: XD-ADR-0109
decides: XD-RULE-0015, XD-RULE-0016, XD-RULE-0017, XD-RULE-0019

ID format <DOMAIN>-<KIND>-<NNNN> with a 4-digit number. Domains are SYS, SW, EE, ME, INT. Examples: SYS-REQ-0012, SW-TC-0103, EE-CMP-0007. Test results: TR-<test case ID>-<run hash>.
Framework Decision: No project code in the sources XD-ADR-0072
status: valid
legacy_id: D79
date: 2026-11-14
decision_status: accepted

No project code in the sources. A project code with the separator : (e.g. RA:SYS-REQ-0012) is added only where IDs leave the workspace: bundles, published needs.json, shared affirmatrix cases.

Framework Decision: Tests live by what they verify XD-ADR-0104
status: valid
legacy_id: D115
date: 2026-11-14
decision_status: accepted

Tests live by what they verify. A test that verifies a SYS-REQ or SYS-IF lives in robarm-integration, even if it touches one domain only. Tests of domain requirements stay in their domain repo.
Framework Decision: Decisions become sphinx-needs XD-ADR-0109
status: valid
legacy_id: D120
date: 2026-11-14
decision_status: accepted
refines: XD-ADR-0071
refined by: XD-ADR-0110
decides: XD-RULE-0015

Decisions become sphinx-needs. Framework decisions are XD-ADR-nnnn in the xdmod manual. Robot-arm decisions are PRJ-DEC-nnnn in the robarm overview doc (robarm-manifest). The old D-number is kept as legacy_id. New ID domains XD and PRJ (extends ID format DOMAIN-KIND-NNNN (XD-ADR-0071)). In rst, every mention of a decision (and of a rule or check) is a real ``:need:`` reference.

date: 2026-11-14
