curatrix command line

Run every command from the workspace root. curatrix <command> --help prints the same text as below. This page is generated from curatrix’s argument parser.

XDMOD workspace command layer (run from the workspace root).

Command

Does

curatrix env

print the workspace environment: eval “$(curatrix env)”

curatrix run

run any command with the workspace env and limits (limits.yaml)

curatrix fixtures

run the planted error of every built-in check (also the tool-backed ones) and record the result

curatrix limits

show the resolved limits table and backend

curatrix doctor

check tools, versions (tools.yaml), paths, hooks, west state

curatrix bootstrap

set up the workspace for a role (group filter, venv, tools, hooks)

curatrix run

run any command with the workspace env and limits (limits.yaml).

usage: curatrix run [-h] [--use USE] [-m MEMORY] [-t TIMEOUT] [-v] ...

positional arguments:
  cmd

options:
  -h, --help            show this help message and exit
  --use USE             limits.yaml use (default: script)
  -m, --memory MEMORY   memory limit, e.g. 2G (overrides the use)
  -t, --timeout TIMEOUT
                        timeout, e.g. 10m or none (overrides the use)
  -v, --verbose

curatrix check

run a repo’s checks (checks.yaml) for a stage.

usage: curatrix check [-h] [--stage {local,pr,full,baseline}] [--no-cad]
                      [--only ONLY] [--base BASE] [--json]
                      [repo]

positional arguments:
  repo

options:
  -h, --help            show this help message and exit
  --stage {local,pr,full,baseline}
  --no-cad              skip checks that need CAD tools (CI)
  --only ONLY           comma list of check IDs or prefixes, e.g. CK-D,CK-C1
  --base BASE           folder with the needs.json files to diff against
                        (CK-G1/G2)
  --json                print the summary JSON on stdout (log on stderr)

curatrix gen

generated files: stubs, model, cad-needs, code-needs, freecad-json, tombstones, all; cad-exports (build/<area>/cad, not committed).

usage: curatrix gen [-h] [--check] [--needs NEEDS [NEEDS ...]]
                    [--textconv FCSTD] [--shape]
                    {stubs,model,cad-needs,connectors,code-needs,freecad-json,tombstones,cad-exports,all}
                    [repo]

positional arguments:
  {stubs,model,cad-needs,connectors,code-needs,freecad-json,tombstones,cad-exports,all}
  repo

options:
  -h, --help            show this help message and exit
  --check               only compare with the committed files
  --needs NEEDS [NEEDS ...]
                        stubs: needs.json files instead of the last docs build
  --textconv FCSTD      freecad-json: print the trace JSON of one file (git
                        textconv)
  --shape               freecad-json: add the shape part (needs FreeCAD)

usage: curatrix new [-h] [--repo REPO] [--no-kicad] {pcba} element

positional arguments:
  {pcba}
  element      the board def (name, qualified name or EE-PCBA ID) in the
               repo's model.json

options:
  -h, --help   show this help message and exit
  --repo REPO  the EE repo (name or path; default: the repo of the current
               folder)
  --no-kicad   do not let KiCad save the new files (tests)

curatrix ci

CI helpers: `ci siblings` resolves sibling revisions (D127); `ci base` fetches the published needs as the CK-G1/G2 base.

usage: curatrix ci [-h] [-o OUT] [--version VERSION] [--branch BRANCH]
                   --repo REPO [--sha SHA]
                   {siblings,base}

positional arguments:
  {siblings,base}

options:
  -h, --help         show this help message and exit
  -o, --out OUT      base: output folder (default build/ci/base)
  --version VERSION  base: the Pages folder (latest = main, vX.Y.Z = a
                     baseline)
  --branch BRANCH    siblings: the PR's head branch name (push: the branch
                     pushed)
  --repo REPO        west name of the repo under check
  --sha SHA          its PR head commit

curatrix evidence

test run records: record (Twister dir -> evidence branch), read (-> TR needs), preview (Twister dir -> preview TR needs for the docs), validate.

usage: curatrix evidence [-h] [--config CONFIG] [--kind {sim,hil}]
                         [--setup SETUP] [--tests TESTS] [--map MAP]
                         [--note NOTE] [--repo REPO] [--branch BRANCH]
                         [--create] [--trailer TRAILER] [--dry-run]
                         [--offline] [--ref REF] [--commit-of COMMIT_OF]
                         [-o OUT]
                         {record,read,preview,validate} [target]

positional arguments:
  {record,read,preview,validate}
  target                record, preview: Twister output dir; validate:
                        record.json

options:
  -h, --help            show this help message and exit
  --config CONFIG       record: the SYS-CFG of the run (required); preview:
                        optional
  --kind {sim,hil}      hil: on the HIL setup; sim: native_sim/QEMU (never HIL
                        evidence)
  --setup SETUP         record --kind hil: the setup folder hil/<setup>
  --tests TESTS         record, preview: test source folders for the ZTEST ->
                        test case IDs (default: Twister's testsuite roots)
  --map MAP             TEST=ID: test case ID for a Twister test (overrides
                        the source comments)
  --note NOTE
  --repo REPO           the repo with the evidence branch (default: the
                        framework repo named <project>-integration)
  --branch BRANCH       evidence (default) or a scratch branch for records
                        that are not evidence
  --create              create the branch as an orphan if it does not exist
  --trailer TRAILER     trailer line for the commit (agents: Co-Authored-By:
                        ...)
  --dry-run             record: print the record, write nothing
  --offline             record: don't check main/baseline at the remotes (the
                        rule then fails)
  --ref REF             read: a git ref instead of the remote branch
  --commit-of COMMIT_OF
                        preview: the repo whose commit the stamp records (the
                        docs show the preview only for that commit)
  -o, --out OUT         read: output file (default build/<repo>/evidence/tr-
                        needs.json); preview: output file (required)
