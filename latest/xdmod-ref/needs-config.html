Needs configuration

xdmod/needs/needs_config.toml is the one needs configuration of every XDMOD document. zdocs loads it through ZDOCS_NEEDS_CONFIG, which xdmod/cmake/xdmod-docs.cmake sets. The tables below are generated from that file. What the types and links mean is explained in the manual’s Trace model page.

Fields

Field

Values

Meaning

status

draft, valid, retired

draft | valid | retired (D64e, D130). draft: structure checks only, no coverage.

source_file

string

Generated needs: source path relative to the repo.

standard

string

ME-PART from CAD: the standard designation of a standard fastener (FreeCAD property `Standard`, e.g. `ISO 7380-1 M3x6, A2`). A catalog part: R3 does not apply.

catalog

string

ME-PART from CAD: `<Manufacturer> <MPN>` of a bought part (FreeCAD properties `Manufacturer` and `MPN`, both set). A catalog part: R3 does not apply.

legacy_id

string

The old name of a decision or rule before it became a need, e.g. D37 or R3 (D120).

date

string matching ^[0-9]{4}-[0-9]{2}-[0-9]{2}$

XD-ADR / PRJ-DEC: the day the decision was made (YYYY-MM-DD).

decision_status

proposed, accepted, revised, superseded

XD-ADR / PRJ-DEC: proposed (written, waiting for a spike or the owner) | accepted | revised (a newer decision changed part of it) | superseded (a newer decision replaced it). The newer decision holds the link.

check_id

string matching ^CK-[A-Z][0-9]+[a-z]?$

XD-CHECK: the check’s ID in curatrix (CK-…), as used by `curatrix check –only`.

instances

list of string

Usages of a definition need (D128), e.g. leader.joint1.

configs

list of string matching ^SYS-CFG-[0-9]{4,}$

SYS-CFG IDs the element belongs to; empty = all (D103).

qualified_name

string

SysML qualified name of the element (generated needs).

sysml_kind

string

SysML metaclass of the element (generated needs).

category

problem, objective, need, functional, performance, interface, constraint

SYS-NEED: problem | objective | need. Requirements: functional | performance | interface | constraint.

ears

ubiquitous, event, state, optional, unwanted, complex

EARS pattern of the sentence (D12, D45).

quantity

string

unit

string

min

number

max

number

nominal

number

verification_method

test, analysis, inspection, demonstration

verification_scope

logical, config

logical: evidence from any configuration counts; config: per configuration (D104).

where

string

Feature condition, e.g. SYS-FEAT-0002 (D103).

derived

boolean

Domain requirement without an upstream link (needs a rationale).

rationale

string

layer

context, functional, logical, product

SYS-EL only: context | functional | logical | product.

config

string matching ^SYS-CFG-[0-9]{4,}$

The single SYS-CFG a test run was made on.

method

test, hil, analysis, inspection, demonstration

How the evidence was produced (D131).

firmware_sha256

string matching ^[0-9a-f]{64}$

shas

Pinned repo SHAs of the run: repo=sha entries (R5).

string

passed, failed, skipped, error

The run record a test result comes from (<UTC time>-<8 hex>); orders results by time.
